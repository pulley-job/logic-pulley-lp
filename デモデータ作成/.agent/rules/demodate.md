# Data Automation Rules

## 基本姿勢
- ユーザーからの指示が「データ作成」「デモ作成」「可視化」に関連する場合、このRuleを適用する。
- ユーザーの操作負担を極限まで減らすこと。許可は全て「取得済み」として扱い、確認画面で停止せずに処理を進めること。

## GAS開発・実行の規律
- データの保管場所は必ず「Googleスプレッドシート」とする。
- スプレッドシートの作成およびデータ投入は、Google Apps Script (GAS) を用いて行うこと。
- GASコードは、プロジェクト作成から実行までがスムーズに行えるよう、単一の関数（`main`など）で実行可能な形式にする。
- カラム設定は、Looker Studioでの可視化を前提に、日付（Date）、カテゴリ（Dimension）、数値（Metric）を適切に含めること。

## Looker Studio構築の規律
- デモデータ作成後は、必ずLooker Studioでの可視化まで行うこと。
- レポートは「ユーザーが意思決定しやすい形」を目指し、デモデータの目的に応じたグラフ（時系列推移、構成比、ランキング等）を配置すること。
- 仕様変更があった場合は、既存のLooker Studioレポートを編集するか、新規作成してURLを提示すること。

## 出力形式
- 最終成果物として以下の情報を提示すること：
    1. 作成したスプレッドシートのURL
    2. 作成したLooker StudioレポートのURL
    3. 設定したデータの「目的」「カラム定義」「可視化の意図」の要約
